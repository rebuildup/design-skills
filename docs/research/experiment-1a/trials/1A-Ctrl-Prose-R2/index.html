Kestrel Trace v1.4 は、バックエンドエンジニア・プラットフォームエンジニア・SRE のためのローカルファースト分散トレース＆フレームグラフプロファイラです。クラウド APM へ送信せず、開発機や CI 上だけで p99 テールレイテンシ悪化の原因を特定できます。

macOS / Linux · 18 MB static binary 
$brew install kestrel-trace/tap/kestrel
18 MB 単一静的バイナリ
0 Docker・外部送信なし
340 ms 48,200 スパン取込
42 MB 常駐メモリ消費
$ kestrel diff main..HEAD 仕様モデル / サンプル
main p99:102 ms HEAD p99:186 ms delta:+84.0 ms
kestrel check --p99-max 120ms · FAIL (exit 1)
checkout.reserve_inventory → SELECT * FROM sku_locks (×14) src/inventory/lock.rs:142

重複するプリペアドステートメントを自動集約し、N+1 反復（14 回、+84.0 ms）を該当行へ直接リンクします。各行をクリックしてスパン詳細を切り替えられます。

01 / Workflow

収集・差分特定・CI 防御を 3 つのコマンドで完結

PR のマージ前後に突然 p99 レイテンシが悪化しても、本番クラウド APM を待つ必要はありません。普段のテストや負荷スクリプトにそのまま組み込めます。

STEP 01 · CAPTURE

設定不要で OTLP をローカル収集

kestrel watch --port 4317

gRPC / HTTP の OTLP スパンをローカルの SQLite と DuckDB のリングバッファへ自動保存。W3C Trace Context を介し、Rust の tracing、Go の otel、Node/Bun サービスをまたぐ呼び出しを 1 本のタイムラインに連結します。

[sample] listening OTLP gRPC/HTTP on :4317
ring-buffer: sqlite+duckdb (local only)
linked runtimes: rust-tracing, go-otel, bun
STEP 02 · DIFF

ブランチ間の回帰スパンと N+1 を特定

kestrel diff main..HEAD

テストや負荷スクリプト実行後、ブランチ間の同一トレースを Span Waterfall と Differential Flamegraph 上に重ね合わせます。重複するプリペアドステートメントを自動集約し、アプリケーションの file:line へ直接結びつけます。

[sample] regression: checkout.reserve_inventory
SELECT * FROM sku_locks ×14 (+84.0 ms)
origin: src/inventory/lock.rs:142
STEP 03 · GATE

CI 予算チェックと HTML スナップショット

kestrel check --p99-max 120ms

原因修正後は CI パイプラインへ組み込み、p99 予算を超えた時点で非ゼロ終了。PR へそのまま添付できる自己完結型の HTML スナップショットを出力し、レイテンシ回帰の再発を食い止めます。

[sample] p99 94.2 ms <= 120 ms (exit 0)
artifact: ./kestrel-snapshot-pr418.html
self-contained report ready for PR
02 / Local-First Design

Docker 不要、外部送信なし。エアギャップ環境でもそのまま稼働

常駐しても開発機を圧迫しない軽量さと、機密トレースを外へ出さないセキュリティ境界を単一バイナリで両立しています。

18 MB BINARY

macOS / Linux 単一静的バイナリ

コンテナエンジンや JVM、外部クラスタの起動は不要。Homebrew または単一シェルコマンドで即座に導入できます。

ZERO TELEMETRY

完全オフライン・エアギャップ対応

トレースやメトリクスの外部送信は一切行いません。閉域網や厳格なデータ持ち出し制限のある開発環境でもそのまま動作します。

SQLITE + DUCKDB

ローカルリングバッファ格納

OTLP スパンをローカルの SQLite と DuckDB へ高速に取り込み、ブランチ差分集計や p99 算出を手元で完結させます。

W3C TRACE CONTEXT

多言語サービスを 1 本に連結

Rust tracing、Go otel、Node/Bun 間の分散呼び出しを標準ヘッダで自動連結し、境界をまたぐ遅延を可視化します。

03 / Resource & Latency Benchmark

ローカル常駐に耐える取り込み速度と省メモリ設計

Docker コンテナ群やクラウド APM の反映待ちに開発リズムを止められません。標準テスト条件における各構成の負荷と遅延を比較しています。
