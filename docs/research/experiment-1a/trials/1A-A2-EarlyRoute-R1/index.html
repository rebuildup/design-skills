WORKFLOW · 4 STEPS FROM LOCAL TO CI

起動から CI ゲートまで、4 つのコマンドで完結

コンテナ構成やクラウド側のアカウント設定は不要。既存のテスト・負荷スクリプトをそのまま OTLP エンドポイントへ向けるだけです。

zsh — kestrel watch --port 4317 SAMPLE OUTPUT

CORE ARCHITECTURE · 6 CAPABILITIES

ローカル実行と決定的な回帰検出のために設計

01 ZERO-CONFIG OTLP

ゼロ設定 OTLP 取り込み

kestrel watch --port 4317 を実行するだけで gRPC / HTTP の OTLP スパンを受信し、ローカルの SQLite + DuckDB リングバッファへ自動収集します。スキーマ設定や外部データベースの起動は不要です。

OTLP :4317 / :4318 → Kestrel Ingest (42 MB) → SQLite + DuckDB
02 DIFF PROFILING

インタラクティブ Span Waterfall & Differential Flamegraph

main と HEAD の同一トレースを重ね合わせ、p99 テールレイテンシの回帰箇所をミリ秒差分で即座に強調表示します。全体のフレームグラフから個別のスパン詳細までシームレスに掘り下げ可能です。

03 SQL & N+1

SQL & N+1 クエリ帰属

重複するプリペアドステートメントを自動集約し、問題のクエリをアプリケーションの file:line へ直接リンク。ORM やループ内の隠れた N+1 を推測なしで突き止めます。

04 CI LATENCY GATE

決定的な CI レイテンシ予算ゲート

kestrel check --p99-max 120ms が予算超過時に非ゼロ終了（exit 1）を返し、PR にそのまま添付できる自己完結型 HTML スナップショットを生成します。

05 AIR-GAP & PRIVACY

オフライン完結・プライバシー保護

18 MB の単一静的バイナリ（macOS / Linux）で完結。外部へのテレメトリ送信は一切なく、決済データや PII を含む機密ペイロードもエアギャップ環境内で安全に検証できます。

06 W3C TRACE CONTEXT

クロス言語トレース連結

W3C Trace Context を介して Rust（tracing）・Go（otel）・Node / Bun サービス間の呼び出しを単一のタイムラインに統合。マイクロサービス境界をまたぐボトルネックを見逃しません。
