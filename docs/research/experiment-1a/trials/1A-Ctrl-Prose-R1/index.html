手元の端末と CI だけで、
p99 回帰をマイクロ秒単位で突き止める。

Kestrel Trace v1.4 は、Rust・Go・TypeScript マイクロサービスを扱うバックエンドエンジニア、プラットフォームエンジニア、SRE のためのローカルファースト分散プロファイラです。本番クラウド APM へトレースを送らず、18 MB 単一静的バイナリだけで原因スパンと N+1 クエリを特定します。

01 · WORKFLOW

収集・差分特定・CI ゲートまで、3 コマンドで完結

PR のマージ前後に突然悪化する p99 レイテンシを、本番環境へ出す前に手元のテストや負荷スクリプトから直接追い込めます。

STEP 01 Zero-Config OTLP

ローカルで OTLP スパンを自動収集

ポート 4317 で待機させるだけで、gRPC / HTTP の OTLP スパンをローカルの SQLite + DuckDB リングバッファへ取り込みます。W3C Trace Context を介し、Rust tracing・Go otel・Node/Bun サービスをまたぐ呼び出しも 1 本のタイムラインへ連結します。 

$kestrel watch --port 4317
STEP 02 Waterfall & Flamegraph

ブランチ間の回帰スパンをミリ秒差分で可視化

普段のテストや負荷スクリプトを実行後にブランチ差分を比較。同一トレースを重ね合わせた Span Waterfall と Differential Flamegraph 上で回帰スパンが浮かび上がり、重複するプリペアドステートメントを自動集約して file:line へ結びつけます。 

$kestrel diff main..HEAD
STEP 03 CI Latency Budget

CI で予算超過を遮断し、スナップショットを出力

修正後は CI パイプラインにレイテンシ予算チェックを組み込むだけ。p99 が閾値を超えた時点で非ゼロ終了し、PR へそのまま添付できる自己完結型の HTML スナップショットを吐き出して再発を食い止めます。 

$kestrel check --p99-max 120ms

03 · OVERHEAD & BENCHMARK

ローカル常駐に耐える圧倒的な軽さと即時取り込み

開発機のメモリを圧迫するコンテナ群や、反映待ち・従量課金が発生するクラウド APM と比較し、手元での反復開発に最適化した性能プロファイルを備えています。

標準テスト条件: 12 サービス構成の決済トレース（48,200 スパン）
