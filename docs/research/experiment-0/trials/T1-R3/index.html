Kestrel Trace は、データを外に出さないローカルファーストの分散トレース＆フレームグラフプロファイラです。手元と CI で、マイクロ秒単位のテールレイテンシ回帰を特定します。

  • 18 MB 単一静的バイナリ
  • 0 テレメトリ送信
  • Docker 不要 エアギャップ可
インストール手順を見る 差分フレームグラフを試す

    Features

    6 つの機能、すべてローカルで完結

    01

    ゼロ設定 OTLP 取り込み

    kestrel watch --port 4317 を起動するだけ。gRPC / HTTP スパンをローカルの SQLite + DuckDB リングバッファへ自動収集します。

    02

    Span Waterfall & Differential Flamegraph

    main と HEAD の同一トレースを重ね、p99 レイテンシの回帰箇所をミリ秒差分で即座に強調表示します。

    03

    SQL & N+1 クエリ帰属

    重複するプリペアドステートメントを自動集約し、問題のクエリをアプリケーションの file:line へ直接リンクします。

    04

    決定的な CI レイテンシ予算ゲート

    kestrel check --p99-max 120ms は閾値超過で非ゼロ終了。PR に添付できる自己完結型 HTML スナップショットを生成します。

    05

    オフライン完結・プライバシー保護

    18 MB の単一バイナリ、外部送信なし。機密ペイロードもローカルだけで検証できます。

    06

    クロス言語トレース連結

    W3C Trace Context を介し、Rust (tracing)・Go (otel)・Node/Bun サービス間の呼び出しを単一タイムラインに統合します。

    Workflow

    4 コマンドで、回帰の発見から再発防止まで

    1. コレクタを起動

      kestrel watch --port 4317

      ローカルでコレクタが待ち受けを開始します。

    2. トレースを収集

      cargo test   # 既存のテストや
./load.sh    # 負荷スクリプト

      普段のテストや負荷スクリプトを実行するだけです。

    3. 回帰スパンを特定

      kestrel diff main..HEAD

      SELECT * FROM sku_locks が 14 回反復し +84ms、のような原因まで辿れます。

    4. CI で再発を防止

      kestrel check --p99-max 120ms

      超過時は非ゼロ終了し、HTML スナップショットを残します。
