テールレイテンシの回帰を、

Kestrel Trace は、データを本番クラウド APM に送らないローカルファーストの分散トレース＆フレームグラフプロファイラ。開発機と CI の上で、p99 の回帰を生んだスパンまで辿れます。

インストール 差分を試す
  • 18 MB単一静的バイナリ
  • 0テレメトリ送信
  • Docker不要
$ kestrel watch --port 4317
✓ OTLP gRPC/HTTP listening
$ kestrel diff main..HEAD
+84ms checkout.reserve_inventory
  SELECT * FROM sku_locks ×14
$ kestrel check --p99-max 120ms
✗ exit 1 · snapshot.html

4 ステップで回帰を捕まえる

  1. kestrel watch --port 4317ローカルコレクタを起動
  2. make load-test既存テストや負荷スクリプトでトレース収集
  3. kestrel diff main..HEADcheckout.reserve_inventory 内の SELECT * FROM sku_locks が 14 回反復し +84ms
  4. kestrel check --p99-max 120msCI に組み込み再発を防止

6 つの主要機能

01

ゼロ設定 OTLP 取り込み

kestrel watch --port 4317 だけで gRPC / HTTP スパンをローカル SQLite + DuckDB リングバッファへ自動収集。

02

Span Waterfall & Differential Flamegraph

main vs HEAD の同一トレースを重ね、p99 回帰箇所をミリ秒差分で強調表示。

03

SQL & N+1 クエリ帰属

重複するプリペアドステートメントを集約し、問題のクエリをアプリケーションの file:line へ直接リンク。

04

決定的な CI レイテンシ予算ゲート

kestrel check --p99-max 120ms は超過時に非ゼロ終了し、PR 添付用の自己完結型 HTML スナップショットを生成。

05

オフライン完結・プライバシー保護

18 MB 単一バイナリ、外部送信なし。機密ペイロードもローカルで検証でき、エアギャップ環境でも動作。

06

クロス言語トレース連結

W3C Trace Context で Rust (tracing)・Go (otel)・Node/Bun 間の呼び出しを単一タイムラインに統合。
