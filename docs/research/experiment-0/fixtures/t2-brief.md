# T2 Brief — Harborline Release & Build Fleet Dashboard

## タスク依頼

リポジトリ内の構造化フィクスチャデータ `data/fleet-metrics.json` を読み込み、オンコール担当のリリースエンジニアが現在の障害状況と過去 24 時間のビルド・デプロイ健全性を把握・切り分けできる **新規運用ダッシュボード**（静的 Web アプリ、`index.html` エントリーポイント）を作成してください。

- 完成 UI やデザインモックは存在しません。
- ビルド不要で、ローカル HTTP サーバー経由で `index.html` を開いたときに `data/fleet-metrics.json` を `fetch` して描画・動作すること。
- 以下の情報とインタラクティブ操作をすべて満たすこと:
  1. **現在の優先トリアージ状況**: アクティブな重大障害（`checkout-api` の SLO 超過・高エラー率・インシデント内容）と警告（`search-indexer`）を迅速に把握できること。
  2. **過去 24 時間の推移**: `hourlyMetrics`（デプロイ数、失敗数、p50/p95/p99 レイテンシ、エラー率、キュー滞留）の変化、特に `06:00Z` 以降の急変を把握できること。
  3. **サービス別 SLO 健全性（6サービス）**: 重要度ティア（`tier1`–`tier3`）、ステータス、p99 vs SLO 目標、エラー率、担当チーム、最終デプロイ ID を確認でき、サービス選択で詳細を確認できること。
  4. **ビルドランナープール稼働状況（4プール）**: `active / capacity`、`queued`、平均待ち時間 `avgWaitSec` の逼迫度比較。
  5. **直近デプロイ履歴（8件）**: ステータス（`all` / `failed` / `rolled_back` / `succeeded`）やサービスで絞り込み、個別のデプロイ詳細（commit, author, duration, canaryDeltaMs）を確認できること。
- デスクトップ（1440px）とモバイル（390px）で崩れなく閲覧・操作できること。
- データの数値を改変・省略せず、フィクスチャの事実を正確に表示すること。
