# T3 Brief — Fieldnote Spec Review Workbench (Authorized Redesign)

## タスク依頼（明示的に許可された再設計スコープ）

このリポジトリには、すでに動作している既存の技術仕様レビュー UI（`index.html`, `styles.css`, `app.js`, `assets/fieldnote-mark.svg`, `data/reviews.json`）が存在します。

現行 UI は機能としては動作していますが、全体が文章主体・単調な縦積み・同型ボックスの反復に依存しており、高リスク案件（P0 や高リスクスコア）の識別、レビュー進捗やリスク分布の把握、一覧を見ながらの詳細レビュー・判定作業に大きな摩擦があります。

**本タスクでは、既存 UI の視覚表現・情報階層・空間構成の再設計が明示的に許可されています。** 以下の維持条件を満たした上で、レビュー担当者が直感的かつ効率的に優先案件を把握し、詳細確認と判定を行える UI へ再設計してください。

### 必須の維持条件（壊してはならない既存要素・機能）
1. **既存アセットとデータ正本の利用**: `assets/fieldnote-mark.svg` と `data/reviews.json` をそのまま活用すること（`data/reviews.json` の内容改変不可）。
2. **全 7 件の仕様データ表示**: 各仕様の ID・タイトル・オーナー・ドメイン・優先度・ステータス・リスクスコア・レイテンシ予算影響・チェックリスト進捗・差分統計・タイムライン・要約を確認できること。
3. **既存インタラクティブ機能の完全維持**:
   - ステータスフィルタ（`all` / `needs-review` / `changes-requested` / `approved`）
   - タイトル / ID / オーナー / ドメインによるリアルタイム検索
   - 仕様の選択と詳細表示の同期
   - 詳細画面内のチェックリスト項目のトグル（進捗件数・表示の即時更新）
   - 「Approve Spec」「Request Changes」操作によるステータス即時更新と集計件数の再計算
4. **レスポンシブ & 基本アクセシビリティ**: デスクトップ（1440px）とモバイル（390px）の両方で崩れなく操作でき、キーボード操作と判読性を保つこと。
5. **ビルド不要の静的構成**: `index.html` からローカル HTTP サーバー経由で直接動作すること。
